# Design and review of the seed

## Where existing work reaches

The research hypothesis is that a small application profile can make an operator's data-use decision and an independent energy-AI evaluation joinable through the same released model. The technical deliverable is the set of identifiers, typed links, integrity rules and queries that implement that hypothesis. Novelty of the individual concepts, universal priority and formal standards status are unestablished. The comparison below is a targeted prior-art review.

| Prior work | Existing coverage | Consequence for EDSO |
|---|---|---|

## Decisions on the seed vocabulary

| Seed terms or assumptions | Decision and rationale |
|---|---|
| DataSpaceParticipant, operatorRole, memberStateCode | Use PROV agents, locations and qualified roles when needed. One organisation may hold different roles per activity. A TEF facility has an operator and an execution location. Use controlled geographical identifiers for cross-country studies. |
| DataSpaceConnector, operatesConnector, exposesDataset, SovereignEnergyDataset | Describe the published service with DCAT, its publisher with Dublin Core and the versioned data with DCAT. The example exposes a catalogue description. A data-service type alone says little about software, access mode, enforcement or physical data movement. |
| GovernanceAgreement, governedByPolicy | Express a concluded agreement as odrl:Agreement with parties, action and target. odrl:Set represents a generic collection of rules. Link the dataset through odrl:hasPolicy. Add the separately attributed and dated decision applied to this execution. |
| GridAsset equivalent to CIM PowerSystemResource | Drop the equivalence. PowerSystemResource can include organisational entities, while the seed described only physical assets. Select the operator's actual CIM/CGMES release, namespace and profile before asserting a mapping. [CIM profile example](https://www.cim4.no/Models/Profiles/Operation/AbstractClasses/PowerSystemResource/) |
| CongestionAnomalyEvent, hasObservation | An anomalous grid condition, a sensor observation and a prediction of a future overload have different times and provenance. Carry observation records in the source SOSA profile and use separate event or forecast identifiers. [SSN/SOSA](https://www.w3.org/TR/vocab-ssn/) |
| FlexibilityOffer, providesFlexibility, BidirectionalEVCharger, IEC 63110 EVSE | ETSI v2.1.1 publishes s4ener:FlexOffer and reuses saref:Device. Producers can include agents and devices. IEC 63110-1 documents charging/discharging management architecture. The seed EVSE URI is unverified and general EVSE can include unidirectional chargers. Drop the exact match and the implied certification. [ETSI](https://saref.etsi.org/saref4ener/v2.1.1/) · [IEC](https://webstore.iec.ch/en/publication/60000) |
| maxDischargePowerKW, stateOfChargePercent | Represent power limits as capabilities with quantity and unit. Model battery state of charge as an observation with time, unit and battery identity. The charger and the battery can have different owners and lifetimes. |
| FederatedTrainingRound, participatesInRound, producesModel, FoundationModelRelease, modelFamily | Separate local activity, update, aggregation, checkpoint and versioned release. PROV supplies most edges. The model release specialises ml:MachineLearningModel. Use dct:type for a family identifier. A round can exist independently of a public release. |
| dpEpsilonBudget, dpDeltaBound, secureAggregationScheme | Separate reported expenditure/bound from a ceiling at the same delta and accounting scope. Record protected unit, neighbouring relation, population, accounting method and source. A secure aggregation protocol is independently documented implementation evidence. Combining epsilon values across rounds requires an accountant and explicit assumptions. [NIST SP 800-226](https://csrc.nist.gov/pubs/sp/800/226/final) |
| SyntheticEnergyDataset, derivedFromSovereignData, syntheticFidelityScore | Represent the generation process and link known sources using PROV. A versioned metric and unit qualify each measurement. A useful corpus may have independent fidelity, utility and disclosure-risk measurements. Privacy guarantees and redistribution rights require separate evidence. |
| AIGymBenchmarkTask, validatedByTask | A plan can be used many times. Put model version, holdout, scenario, setting, evaluator and baseline on the execution, then attach a measured score. This preserves results from distinct TEF scenarios as first-class records. |
| AIActConformityFile, hasConformityFile, trlLevel | Assemble evidence for an intended deployment and attribute its review. An applicable legal obligation or TRL claim requires its own assessment, actor, date, scope and evidence. Structural validation does not confer certification. [EU AI Act, Annex IV](https://ai-act-service-desk.ec.europa.eu/en/ai-act/annex-4) |
| osiLicenseIdentifier, proposed w3id and external stubs | Use dct:license with the licence IRI of each artifact. Dataset, code and model licences can differ. Preserve this repository's MIT licence. The draft uses a repository-controlled namespace. Third-party terms retain their own definitions and property kinds. |

## Semantics of the checks

The OWL vocabulary defines reusable meanings. The SHACL profile describes a deliberately narrow exchange contract for explicit, single-input contributions and single-release runs. One round can accept multiple contributions. A local decision check requires an explicit matching ODRL permission and the recorded permit by execution time. Production policy engines can additionally consider duties, expiry, prohibitions, identity and revocation. Attach their machine-generated decisions and supporting evidence in an access-controlled store.

The privacy query compares a reported bound with a ceiling attached to the same statement. A correctly reported breach should remain visible. An absent account means this graph supplies no bound. Synthetic generation alone supplies no privacy guarantee. A TEF label records the reported setting. Institutional independence calls for evidence about the evaluator and its relationship to the developer.

The matched-evaluation query deliberately requires identical condition identifiers. A TEF may use its own hardware, dataset or stress scenario. Its score still has full provenance. Protocol identifiers should resolve to frozen scoring code, aggregation rules and horizon. Holdout identifiers should resolve to immutable manifests. If editions, unit conversion or statistical equivalence are to be recognised across different identifiers, publish and test a separate comparison rule.
